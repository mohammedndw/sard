PHASE 1 — DATA MODEL + SECURITY (Firebase)
========================================================
Use Firestore collections (suggested):
- users (role: "admin" or "user", name, email, phone, createdAt)
- events
- tickets (ticket types inside events OR subcollection)
- registrations (eventId, userId, ticketTypeId, qty, status, paymentStatus, createdAt)
- bookings (place rental requests: date, time, details, status)
- payments (registrationId, provider, amount, currency, status, createdAt)

Add Firebase Auth:
- Email/password login for Admin
- Users can browse without login, but must login to buy/register tickets

Security rules:
- Only Admin can create/edit/delete events, view registrations list, edit registration status
- Users can only read public events and read their own registrations
- Storage: Admin can upload banners/logos

PHASE 4 — PAYMENT GATEWAY INTEGRATION (Backend + Frontend)
========================================================
Implement a generic payment gateway flow with these backend endpoints in Cloud Functions (Express):
- GET  /api/health
- POST /api/payments/create-session
  Input: registrationId OR eventId + ticketTypeId + qty
  Output: paymentUrl OR sessionId
- POST /api/payments/webhook
  Receives payment provider webhook events and updates:
  - payments.status
  - registrations.paymentStatus
  - registrations.status

Frontend payment flow:
- After user chooses paid ticket, call create-session
- Redirect user to paymentUrl
- After payment success, show success page and update registration status to confirmed

Notes:
- Don’t lock to one provider in code. Build it so we can swap providers later.
- Use environment variables for provider keys.
